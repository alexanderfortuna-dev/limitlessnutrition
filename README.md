# LIMITLESS — Static HTML Storefront

Premium-athletic (Momentous-style) storefront for **LIMITLESS**, a nutrition &
fitness reseller in Bali / Indonesia. The entire shop is **one self-contained
`index.html`** (all CSS, JS, and product data embedded) generated by a Python
script from JSON data. No build step, no framework, no backend — just upload to
static hosting.

## Architecture

```
products.json  ─┐
cats.json      ─┤──►  build_store2.py  ──►  index.html        (remote images via weserv proxy)
                                       └─►  index-clean.html  (local images_clean/<code>.webp)
```

- **`build_store2.py`** — reads `products.json` + `cats.json`, injects the data
  into one HTML template, and writes both outputs. The two files share the exact
  same template; only a `CLEAN_BUILD` flag differs, so the `img()` fallback chain
  (local → weserv proxy → procedural SVG packshot) stays identical.
- **Never hand-edit `index.html`.** Edit `build_store2.py` (template/logic) or the
  JSON data, then re-run the generator.

### Product data (`products.json`)

Array of objects, one per product:

| field | meaning                                   |
|-------|-------------------------------------------|
| `c`   | code / SKU (also the image filename)      |
| `t`   | title                                     |
| `k`   | category key (matches a `cats.json` key)  |
| `i`   | remote image URL (`""` → SVG fallback)    |
| `q`   | confidence / popularity score (0–1)       |
| `price`     | *(optional)* IDR integer            |
| `compareAt` | *(optional)* IDR “before” price     |

If `price` is absent the card shows **“Chat untuk harga”** and the item is
excluded from the cart subtotal (admin confirms total on WhatsApp).

> The repo ships with the **real catalogue** (2,523 products in `products.json`,
> 12 categories in `cats.json`). To refresh, replace those JSON files and re-run
> the generator — nothing else changes. If `products.json` is deleted, the
> generator falls back to auto-seeding a small demo dataset so it still builds.
>
> Prices are not in the source data yet, so every card shows **“Chat untuk
> harga.”** Add `price` (and optional `compareAt`) to products in `products.json`
> and rebuild to activate the price layer + cart subtotal.

### Image pipeline (optional, for `index-clean.html`)

```
python3 rehost_images.py   # download every product image  -> images/
python3 clean_images.py    # rembg BiRefNet cut-outs        -> images_clean/
```

`index.html` works **without** any local images (it proxies remote URLs and falls
back to an SVG packshot). `index-clean.html` serves `images_clean/` locally.

## Build

```bash
python3 build_store2.py
```

## Deploy (Hostinger `public_html/`)

- **Simplest:** upload `index.html` + `logo.png`. Images are proxied/fallback’d.
- **Best quality:** upload `index-clean.html` (rename to `index.html`) +
  `logo.png` + the `images_clean/` folder.

## Configuration — single source of truth

Everything operational lives in the `CONFIG` block at the top of the `<script>`
in `build_store2.py`’s template. Edit there, then rebuild.

```js
const CONFIG = {
  brand:"LIMITLESS",
  waAdmins:["628989755534","6289518200002","6281339229918"], // delivery → random pool
  couriers:["Gojek","Grab","Maxim","Kurir Reguler (JNE/J&T/SiCepat)"],
  branches:[{n:"Cabang Sanur (Pusat)", a:"", wa:""}],          // pickup → that branch's WA
  payEndpoint:"",     // Xendit/Midtrans/n8n endpoint → enables "Bayar Online"
  analyticsId:"",     // "G-XXXX" → GA4, otherwise treated as Meta Pixel ID; empty → nothing
  trust:["Original","BPOM","Halal MUI","COD","Gratis Ongkir","Garansi 30 Hari"]
};
```

### Things to fill in before going live

1. **`waAdmins`** — confirm the 3 admin WhatsApp numbers.
2. **`branches`** — add each branch `{n, a, wa}`. Pickup orders route to that
   branch’s WhatsApp; delivery orders route randomly across `waAdmins`.
3. **`payEndpoint`** — leave empty until your gateway is ready. When set,
   “Bayar Online” POSTs the cart and redirects to the returned `invoiceUrl`;
   on any failure it falls back to WhatsApp checkout. `payOnline()` is the single
   integration point.
4. **`analyticsId`** — set to inject GA4 or Meta Pixel; empty injects nothing.

## Features

Sticky glass nav · mega-menu (categories + goals + featured) · mobile drawer ·
live search w/ thumbnails · category chips + sort (Relevan / **Terlaris** /
**Harga ↑↓** / A–Z) + load-more pagination (20/page) · product cards (SVG
fallback, wishlist, benefit checks, add-to-cart) · quick-view (qty stepper,
related products, **Bagikan via WhatsApp**) · cart drawer with **live IDR
subtotal** and fulfillment choice (delivery courier / branch pickup) ·
branch-aware WhatsApp checkout · wishlist filter · recently-viewed &
best-seller rails · editorial bands · desktop buy-bar · mobile bottom tabs ·
WhatsApp FAB · back-to-top · **Three.js signature product tub** (auto-rotate +
drag, DPR≤2, pauses when hidden, off under reduced-motion) · **shareable deep
links** (`#p=<code>` opens the product) · **JSON-LD** Product + BreadcrumbList +
Open Graph tags · SEO meta + favicon.

## Constraints honored

Single self-contained HTML · no external JS except Three.js (cdnjs) + Google
Fonts · **no localStorage/sessionStorage** (in-memory state) · all `<img
loading="lazy">` · DPR capped at 2 · animations gated behind
`prefers-reduced-motion` · responsive 375 / 768 / 1280 with no horizontal scroll.
